# PCO Generator — Build Log

What happened, in order, and what each finding changed. The 2026-06-19 entries were
reconstructed from the commit history on 2026-11-19.

## 2026-06-19 — v1 to v2: from change order to PCO

v1 generated a generic "change order" (`test_change_order.docx`). v2 retyped it as a
Potential Change Order, structured the scope by CHG-51 (baseline → change → inclusions
and exclusions → assumptions), took the cause categories from the CHG-51 taxonomy,
added a 21-day validity, and applied the 1% + 10% + 10% markup **in code**
(`apply_markup`). Blank costs came out as `[TBD]` throughout.

Sample outputs for two `test_run.py` cases are in the code repository's `output/`:
Johnson (rot under the master bath, $2,400 labor + $680 material) came to a total of
$3,726.80. Sullivan (island extension, no costs given) was correctly all `[TBD]`.

Changed: [design.md decision log](design.md#4-decision-log), entry for v2.

## 2026-06-19 — Live: email delivery, voice input, domain

Added Resend email delivery and voice input on the form, CORS, the verified sending
domain, and the CNAME for draftconstructionchangeorder.com. The form is on GitHub Pages
and the API on Render.

## 2026-06-19 — v3: itemized cost table from SYS-09

Embedded the SYS-09 rate sheet (labeled as 1,258 line items from 12+ projects) in the
prompt and had the model build an itemized cost table, with a cost basis for each line,
from the contractor's numbers as anchors. The model now also does the markup and
totals. `apply_markup` and the `[TBD]` path were removed.

No v3 output was saved. Everything in `output/` is from v2, so the live version's
arithmetic has never been recorded or checked.

Changed: [design.md decision log](design.md#4-decision-log), entry for v3.

## 2026-06-19 — Memory and abuse limits

Cut max_tokens from 2500 to 1500 and ran gunicorn with one worker restarting every ~10
requests to fit Render's memory. Added rate limiting (10 per IP per hour); two follow-up
commits fixed the import and added `flask-limiter` to the requirements.

## 2026-11-19 — Docs written; v3 found to have moved the math into the model

Wrote the brief, spec, design and plan from the code and its history. Findings:

- The brief said prices are "never generated by the model". In v3 they all are, with
  no check. v2 had done the markup in code, so v3 was a step back on the property the
  brief advertises.
- `test_run.py` case 2 still expects `[TBD]` for blank costs. v3 has the model estimate
  them instead.
- The form never collects the original contract sum. "Valid Through" is counted from
  the day the document is generated, not the PCO date. A missing section is dropped
  silently.

Changed: Justin decided to move pricing into code, price SYS-09 ranges at the midpoint,
use the PM's own numbers first with SYS-09 filling the gaps as labelled sample rates,
and drop the T&M clause ([design.md](design.md#4-decision-log)). The app is not being
changed now; M1–M4 ([plan.md](plan.md)) are unscheduled.
